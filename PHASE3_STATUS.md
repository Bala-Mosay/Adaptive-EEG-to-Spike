# Phase 3 Status — Contribution 1 (adaptive KNN-MI bands): complete, negative result

Phase 3 Contribution 1 (per-subject adaptive band selection) is implemented and has
been evaluated over the full 103-subject, 5-fold protocol. It **underperforms the
Phase 2 fixed-band baseline**; the evidence and the likely cause are documented below.

Contributions 2 (learnable spike threshold) and 3 (dual-timescale PLIF with attention
fusion) are **not started**.

Last updated: 2026-11-21.

## Deliverables

1. **7-band filter bank** — `src/bands/bank.py`: theta 4–8, mu 8–12, low_beta 12–16,
   beta 16–20, high_beta 20–24, low_gamma 24–28, gamma 28–32 Hz (paper Section 5.3).
2. **KNN mutual-information scorer** — `src/bands/knn_mi.py`: Kraskov-style KNN MI
   estimator, fitted on the training fold only.
3. **Per-subject top-k selector** — `src/bands/selector.py`: ranks bands per subject on
   training trials, keeps the top `k` (k = 3).
4. **Adaptive-band CSP features** — `src/features/adaptive_bands.py`: one regularized
   CSP per band on the training fold, then each trial keeps its subject's selected
   band blocks. Output dimension `top_k * n_classes * n_components` = 48.
5. **Checkpointed CV runner** — `experiments/run_phase3.py`: per-fold atomic
   checkpoints, config-fingerprint guard, resume, terminal status bars, and coarse
   progress logs for non-interactive runs.
6. **Config** — `config/phase3_config.yaml` (seed 42, 100 epochs, `device: auto`).
7. **Tests** — 71 passing, including leakage guards, a bitwise check that chunked
   band filtering does not change results, and guards that the screening harness
   reproduces the production feature matrices exactly.

## Protocol

5-fold **subject-mixed, trial-level** CV over 103 subjects / 8,672 balanced trials.
Per-subject z-score, per-band CSP filters, the KNN-MI band ranking, and the encoder
threshold are all fit **on the training fold only**. Same protocol as the Phase 2
baseline, so the two are directly comparable in evaluation design.

## Why C1 lost: band-selection diagnostics

Generated by `python scripts/analyze_phase3_bands.py` (output:
`results/phase3_c1/band_diagnostics.json`). Statistics are over 515 subject-fold
selections (103 subjects × 5 folds, 3 bands each).

**Selection frequency** (how often a band survives the top-3 cut):

| Band | Selections | % of subject-folds |
|---|---|---|
| high_beta (20–24) | 316 | 61.4% |
| low_beta (12–16) | 263 | 51.1% |
| mu (8–12) | 239 | 46.4% |
| beta (16–20) | 231 | 44.9% |
| low_gamma (24–28) | 210 | 40.8% |
| gamma (28–32) | 161 | 31.3% |
| theta (4–8) | 125 | 24.3% |

**Instability across folds:**

- Distinct selected band sets per subject across the 5 folds: **mean 3.33, median 3, max 5**.
- Only **5 of 103 subjects** keep an identical set in all five folds.

**Discarding the sensorimotor bands:**

- **276 of 515 (53.6%)** subject-folds discard the classic mu band entirely.
- **65 of 515 (12.6%)** keep no sensorimotor band at all (no mu, low_beta, or beta).

### Interpretation

1. The ranking is **unstable**, not subject-specific. A selector that identified a
   genuine per-subject optimum would reproduce roughly the same set across folds.
   With ~70 training trials per subject and `n_neighbors=5`, the KNN-MI estimate is
   dominated by sampling noise, so the "adaptation" is largely noise.
2. The noise is **not harmless**: it discards mu/beta, the bands with the strongest
   documented motor-imagery evidence, in more than half of subject-folds. The baseline
   keeps them always.
3. Therefore the result does not show "adaptive bands are useless". It shows that
   **this selector, at this sample size, removes signal** and the 3-of-7 reduction is a
   net loss.

### Confounds to resolve before drawing a scientific conclusion

- **Band set and adaptation are entangled.** The baseline uses 2 broad bands
  (32 features); C1 uses 3 narrow bands (48 features). A fixed 7-band control scored
  with a *prior* ordering (e.g. always top-3 by literature rank, or all 7 bands) is
  needed to separate "more/narrower bands" from "per-subject adaptation".
- **top_k = 3 was fixed a priori**, not tuned; k = 5 or k = 7 would bound how much
  signal the selector can throw away.

Candidate follow-ups (each needs its own config fingerprint / run):

1. Fixed 7-band CSP (no selection) — isolates the band-set effect from the selector.
2. Adapt only the *order* while always keeping mu and beta, e.g. 2 fixed + 1 adaptive.
3. Increase `n_neighbors`, or estimate MI on subject-pooled trials with a subject
   indicator, to stabilise the ranking.
4. Raise `top_k` to 5 and report accuracy against k = 3 and k = 7.

## Selector audit and cheap screening

Before spending ~1 hour of SNN training per fold on a candidate fix, the selector was
audited and the candidate feature sets are screened with logistic regression.

**Audit (no defect found).** `AdaptiveBandSelector._select` ranks by `-score`, so the
highest mutual information wins; bands are returned in filter-bank order, so block
positions are stable. `AdaptiveBandCSPFeatures.transform` restricts each trial to its
own subject's bands (covered by `tests/test_adaptive_bands.py`). The screening helpers
are bitwise identical to the production path (`tests/test_band_screen.py`): the
single-pass extractor matches `FixedBandCSPFeatures.fit` + `.transform` exactly, and
the screened column selection matches `AdaptiveBandCSPFeatures.transform` exactly.
The C1 loss is therefore statistical, not a ranking-direction or slicing bug.

**Screen.** `scripts/screen_band_conditions.py` does one 7-band CSP pass per fold and
then scores several conditions on the same fold with logistic regression:

| Condition | Bands | Dims |
|---|---|---|
| `broad_mu_beta` | Phase 2 mu + beta (broad) | 32 |
| `all7` | all seven narrow bands, no selection | 112 |
| `adaptive3` | C1 as run (per-subject top-3) | 48 |
| `adaptive5` | per-subject top-5 | 80 |
| `sensorimotor3` | fixed mu + low_beta + beta | 48 |
| `guarded_adaptive` | mu + beta pinned, plus best remaining | 48 |

The linear classifier is a **proxy**, not a substitute: on identical features Phase 2
measured 34.6% (LogReg) vs 31.8% (SNN). It is used to rank candidates cheaply; the
winning condition still needs a full SNN run for the thesis number.

## Caveats

- **Subject-mixed trial-level CV, not LOSO.** Test folds contain trials from subjects
  seen in training, so this is not a cross-subject generalization result.
- **SynOps numbers are not comparable across phases.** The Phase 2 baseline reports
  0.72 SynOps/trial from the old counter, which was fixed in this phase to sum emitted
  spikes. C1's 1174.1 is from the corrected counter; the baseline must be re-measured
  before any energy comparison.
- Phase 1 preprocessing (ICA, AutoReject, bad-channel interpolation) still runs per
  subject outside the CV loop, as in Phase 2. It does not use labels, but it is
  transductive across folds.
- `S091` is now repaired (all-channel bad-interpolation guard) and all 103 caches pass
  validation, so this run is not affected by the earlier all-zero cache.

## Defects fixed during this phase

1. **`S091` all-zero cache** — `src/data/preprocessing.py`: when every channel is
   flagged bad, interpolation was producing constant/all-zero epochs. Added a guard
   that falls back to the original signal instead of interpolating all channels.
2. **SynOps undercount** — `src/snn/synops.py`: now counts emitted spikes directly
   instead of an approximation that omitted per-layer neuron counts.
3. **Out-of-memory crash on 16 GB machines** — `src/features/bandpass.py`: MNE's FIR
   path upcasts the whole fold to float64 and allocates a full-size output (~4 GB per
   band). Filtering is now chunked at 128 trials, which is **bitwise identical**
   (regression test `test_chunked_band_filtering_is_bitwise_identical`). The runner
   also releases per-subject arrays after concatenation and per-fold train/test
   buffers, cutting peak RSS by ~1.8 GB.
4. **Silent logging** — an imported library configured logging first, so the runner's
   `basicConfig(level=INFO)` was a no-op and progress logs were dropped. Fixed with
   `force=True`, plus coarse progress lines when the status bar is not a TTY.

## Reproduce

```bash
python -u experiments/run_phase3.py --config config/phase3_config.yaml \
    --log-file results/phase3_c1_run.log --resume
python scripts/analyze_phase3_bands.py --json results/phase3_c1/band_diagnostics.json
```

Resume is guarded by config fingerprint `ffadd79d4d707f74` (103 subjects, 8,672
trials, 100 epochs, band bank and `top_k` included). Changing any of those requires
`--overwrite`.

Runtime on CPU: ~30–65 minutes per fold; folds 3–4 resumed from checkpoint took
~59 minutes each.
